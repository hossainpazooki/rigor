fact: hooks/git-guard.mjs's normalizeGitSegment took `argv.join(' ')` and re-split it on whitespace before skipping git's global options, so a quoted option value holding a space became two tokens and shifted the subcommand position: `git -C "a b" commit -m x` was read as subcommand `b` and allowed, as were `merge` and `push` behind the same value - a bypass present since c93cb4c (2026-06-25), the first hook version to skip global options, and carried by the 0.1.0 plugin-cache copy. The same shape sometimes blocked by accident (a second word `merge-x` matched the old `merge\b` rule), which is why narrowing that rule exposed it: two mid-tier skeptics refuting the 2026-09-14 merge fix found `git -C "r merge-x" merge feature` flipping to allowed. The decide() comment said joining argv was safe "because nothing re-splits it positionally" - false, normalizeGitSegment did. Fixed by walking the argv array from expandArgv, the lesson isGhBlocked learned in fix round 3. On 2026-09-15 a second round of skeptics showed the argv walk alone lost writes where the hook's tokenizer differs from bash, so by operator ruling the old re-split view votes too and either view naming a write blocks (entry 2026-09-15-git-guard-read-an-unlisted-global-flag-as-the-subcommand).
